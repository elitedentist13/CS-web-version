✨ AI Patient Assistant

Warm birthday touches, polite recall reminders, and ready-to-send messages for WhatsApp, SMS, or email — drafted from your prompts so every patient hears a consistent, human voice.

  • Slice patients by age, sex, HK district cues (from address text)
  • Checkbox roster with select-all helpers + smart templated drafts
  • Review before outreach — WhatsApp/SMS/email one recipient at a time
Free to use — try birthday & recall drafts without signing in

Front-desk teams save hours drafting messages while keeping a premium, consistent tone. This module is framed as an add-on: pair it with your subscription tier for differentiation in demos and tenders.

Responsible use: Suggested text only — not medical advice. Omit sensitive health details from prompts sent to external AI services.

Default: the app calls your Supabase project’s Edge Function ai-patient-draft, which validates the logged-in clinic user server-side and calls OpenAI there (never from the browser). Set OPENAI_API_KEY only in Supabase secrets. If the function is missing or errors, Joyful Smile falls back to the optional HTTPS proxy below, then offline demo templates.

Deploy on your Supabase project
  1. Install CLI, then supabase login and supabase link to your project.
  2. Add secret: Dashboard → Functions → Secrets → OPENAI_API_KEY (optional OPENAI_MODEL).
  3. Deploy: supabase functions deploy ai-patient-draft
  4. Use the same anon key/project URL already in Joyful Smile (no key change needed).

Drafting works for anyone by default (no login check). Opt-in tightening: add secret AI_REQUIRE_LOGIN=true so only active app_users can call OpenAI via this route.

Advanced: custom HTTPS gateway (same JSON body + { "message": "…" } response). Include workflow: "memo" plus memoAction, memoBody for memo rewriting.

Include caller fields (callerUserId, callerClinicId) matching the Edge payload if you migrate this route later.

Do not vendor API keys in front-end source — Edge secrets or your backend only.
